Aim and objectives

Provisional project title: Multimodal Image Retrieval and Recommendation System

Overall aim:
This project aims to build a multimodal retrieval, intelligent Q&A, and interactive system based on an LLM agent, utilizing the historical image assets provided by the UK Antarctic Heritage Trust (UKAHT). The system employs a combination of descriptions automatically generated by LLM and a small set of high-quality descriptions manually curated by the team; a domain-projection adaptive module is used to correct conceptual biases inherent in general-purpose multimodal models. Furthermore, an LLM agent serves as the intelligent core, enabling multimodal Retrieval-Augmented Generation (RAG) that supports multi-turn follow-up questions, hybrid retrieval, and interactive assisted annotation, thereby delivering an integrated experience for the intelligent interrogation and search-based recommendation of historical archives.

Specific milestones to complete in order to achieve the overall aim (indicate 3-5):

1. Milestone 1: Working End-to-End Baseline Retrieval Pipeline
- Database: Set up a SQLite database to store image metadata (title, category, description) and CLIP-generated image embeddings, ensuring it can hold both auto-generated and manually written captions.
- API: Build a FastAPI backend providing Search (text-to-image retrieval), Recommendation (similar-image lookup), and Upload-and-Index (ingest a new image with auto-captioning) endpoints.
- UI: A Streamlit image gallery connected to the backend, allowing users to enter a query and browse ranked results.
- Deliverable: A runnable end-to-end pipeline verified on a small sample of UKAHT images, confirming that text queries return relevant results.
- Team Responsibility: Peidong Wang (backend and model inference), Tian Luo (database schema), Chenyu Yuan (Streamlit UI).

2. Milestone 2: Corpus Ingestion, Auto-Captioning, and Golden Test Set Curation
- Ingestion: A batch script that runs BLIP over all UKAHT images to generate captions, computes CLIP embeddings, and stores everything in the database.
- Annotation: A simple Streamlit page where team members can review and correct auto-generated captions, producing a curated golden test set of 50–100 verified image-text pairs. This size is chosen to cover the main thematic categories in the collection (e.g., landscapes, expeditions, equipment, people) while remaining feasible within the project timeline.
- Deliverable: A fully indexed database of all UKAHT images and a golden test set JSON file for downstream evaluation.
- Team Responsibility: Yisheng Zhang (batch ingestion script), Chenyu Yuan (annotation UI).

3. Milestone 3: Polar Domain Adaptation via MLP Projection Adapter
- Model: A lightweight MLP adapter trained with Triplet Loss to project CLIP embeddings into a polar-domain-specific vector space, reducing the gap between general-purpose visual representations and polar expedition imagery.
- Training: Use the golden test set's image-text pairs as positive samples and randomly sampled non-matching pairs as negatives; track loss convergence in a training notebook.
- Deliverable: A trained adapter that demonstrably improves retrieval accuracy on polar images compared to the vanilla CLIP baseline.
- Team Responsibility: Peidong Wang (adapter design and Triplet Loss training).

4. Milestone 4: LLM Agent Integration and RAG Q&A Hub
- Agent: A ReAct-based LLM agent that interprets free-text queries and decides whether to call a semantic vector search tool or a structured SQL metadata filter (or both).
- RAG Pipeline: Retrieved image context and captions are fed back to the LLM to generate a coherent multi-turn answer, with conversation history maintained across follow-up questions.
- UI: A chat interface in Streamlit where users can ask natural-language questions about the archive and receive answers with supporting images.
- Deliverable: A working Q&A interface that correctly answers at least a representative set of test queries using hybrid retrieval.
- Team Responsibility: Tian Luo (agent logic and hybrid search), Chenyu Yuan (chat UI integration).

5. Milestone 5: Quantitative Evaluation and Containerized Deployment
- Evaluation: Compute MAP and nDCG on the golden test set for both the baseline (vanilla CLIP) and the adapted model, and visualise the change in embedding space using t-SNE plots.
- Deployment: Package the FastAPI backend and Streamlit frontend into Docker containers orchestrated with docker-compose, so the full system runs with a single command.
- Deliverable: An evaluation report comparing retrieval quality before and after adaptation, plus a containerised system that any team member can run locally without manual environment setup.
- Team Responsibility: Chenyu Yuan (evaluation metrics and visualisation), Yisheng Zhang (Dockerfiles and docker-compose).

Technology or approach that you plan to use:
1. Multimodal Feature Representation & Generation: Employs a pre-trained CLIP model as a dual-tower encoder for vision and text; utilizes the BLIP model for automated, unsupervised image captioning.
2. Domain Adaptation: Integrates a custom MLP adapter to perform contrastive fine-tuning using Triplet Loss on a semi-mixed supervised triplet dataset, thereby narrowing the distance between image and configuration description embeddings within the high-dimensional latent space.
3. LLM Agent (Central Controller): Uses a Large Language Model (e.g., Gemma 2 or Llama 3.1) as the core processor; implements intent parsing, hybrid search tool invocation, multimodal RAG-based text synthesis, and an interactive intelligent alert assistant based on the ReAct architecture.
4. Academic Evaluation & Visualization: Conducts ablation studies by calculating MAP (Mean Average Precision) and nDCG (Normalized Discounted Cumulative Gain) using human-annotated datasets; visualizes representation shifts by projecting embeddings onto a 2D plane via t-SNE or UMAP algorithms.
Technology Stack: Streamlit; backend powered by Python, FastAPI, PyTorch, and SQLite; deployment configured for Docker and docker-compose.

Data requirements

What data/information do you need to achieve your plan:
Historical expedition photographs and digital captures (where available) of physical photo archives provided by the UK Antarctic Heritage Trust

Is the data needed currently available:
The 3.3 GB photograph archive provided by UKAHT is already available and is sufficient to support Milestones 1–3 (baseline pipeline, ingestion, and domain adaptation). Text annotations and captions do not yet exist; these will be generated automatically by BLIP and subsequently verified by the team as part of Milestone 2. No additional external dataset is required to complete the project.

What is your plan B if the data you need is not fully available (i.e., if the only data that will ever be available to you is what has been shared so far):
Since the photographs alone are the primary data source, the project can proceed entirely with the current dataset. BLIP or an advanced LLM will generate initial automated captions for all image assets; a subset of these captions will then undergo human-in-the-loop review to correct factual or contextual inaccuracies, producing the golden test set needed for evaluation.
